# k81128 只读 API 设计

## 目标

在本机运行一个受保护的只读 API，将 k81128 的赛事与赔率、账户余额、投注记录提供给其他服务器项目使用。服务监听 `127.0.0.1:8788`，通过现有 Cloudflare Tunnel 发布为 `https://k8.nbmrjun.top`。

第一版不支持下注、充值、提现或任何会改变账户状态的操作。

## 对外接口

- `GET /health`：服务状态，不返回账户信息。
- `GET /api/sports`：赛事、开赛时间、盘口与赔率。
- `GET /api/balance`：账户余额及币种。
- `GET /api/bets`：投注记录，支持有限的分页参数。

除 `/health` 外，所有接口要求：

```http
Authorization: Bearer <API_TOKEN>
```

成功响应统一包含 `data`、`source` 和 `fetched_at`。错误响应统一包含稳定的错误码、简短信息和请求 ID，不泄露上游凭证或响应正文。

## 架构

```text
调用方服务器
  -> HTTPS k8.nbmrjun.top
  -> Cloudflare Tunnel
  -> 127.0.0.1:8788
  -> API 鉴权与限流
  -> k81128 数据适配器
  -> 标准化 JSON
```

服务优先直接调用网页使用的后端数据接口。这比解析 DOM 更快、更稳定，也便于测试。若余额或投注记录暂时无法通过稳定接口获取，可增加独立的浏览器采集适配器作为后备；生产服务不依赖 Codex 的 Chrome 控制连接。

## 组件

1. HTTP 服务：路由、参数校验、响应格式和请求 ID。
2. Bearer Token 中间件：使用常量时间比较验证 `API_TOKEN`。
3. k81128 客户端：管理上游地址、超时、会话凭证和错误映射。
4. 数据标准化层：将上游结构转换为稳定的公共模型。
5. Cloudflare Tunnel：在现有 Tunnel 配置中增加 `k8.nbmrjun.top -> http://localhost:8788`。
6. 运行管理：本机启动配置、健康检查和日志轮转。

## 凭证与安全

- API Token 和 k81128 会话凭证只保存在本机环境文件中，不提交到 Git。
- 服务只监听回环地址，不直接开放本机端口。
- 日志不记录 `Authorization`、Cookie、上游 Token 或完整账户响应。
- 默认只允许 `GET`；其他方法返回 `405`。
- 设置上游请求超时、响应大小限制和基本速率限制。
- k81128 会话失效时返回 `UPSTREAM_AUTH_EXPIRED`，不尝试自动输入密码或绕过验证码。

## 数据流与缓存

`/api/sports` 可使用短缓存以降低上游压力，默认 5 秒；余额和投注记录默认不缓存。每个响应标注实际抓取时间。上游超时返回 `504`，登录失效返回 `502` 和稳定错误码，数据结构变化返回 `502 UPSTREAM_SCHEMA_CHANGED`。

## 测试与验收

- 单元测试覆盖 Token 鉴权、参数校验、上游错误映射和数据标准化。
- 使用模拟上游响应测试三个业务接口，不在测试中保存真实凭证。
- 本机验证未授权请求为 `401`，正确 Token 请求成功。
- Tunnel 配置后，从外部网络验证 HTTPS、鉴权和三个接口。
- 验收要求：Token 不出现在源码、Git、测试输出或服务日志中。

## 实施顺序

1. 识别 k81128 的稳定数据接口及认证要求。
2. 创建 API 服务、模型、鉴权和测试。
3. 生成本地密钥配置并启动服务。
4. 更新 Cloudflare Tunnel ingress 与 DNS 路由。
5. 完成本地和外部端到端验证。
